# 笔记系统

三层结构，各司其职：

| 层 | 目录 | 特征 | 寿命 |
| --- | --- | --- | --- |
| 采集 | `capture/` | 粗糙、随手、允许混乱 | 一周内清空 |
| 原子 | `atoms/` | 一个文件一个概念，命名即结论 | 长期，可被引用 |
| 索引 | `index/` | 把原子笔记串成地图 | 长期，随认知更新 |
| 课程 | `lessons/` | 按教材章节的结构化笔记 ＋ 问答骨架，配套 `../planning/` 的 10 分钟任务卡 | 长期，随阶段更新 |

## 为什么要分层

长期项目最常见的失败是"记了很多但用不上"。原因是：

- 把所有东西混在一起 → 找不到
- 只记内容不记条件 → 记错了也不知道
- 没有索引 → 三年后不知道这些笔记之间的关系

## 原子笔记的判定标准

一个文件能不能叫"原子笔记"，看它是否满足：

1. 标题本身是一个**结论**（不是主题）
2. 内容只讲一件事
3. 有成立条件
4. 有一个可验证它的实验或仿真
5. 至少链接到另一条笔记

示例见 `atoms/干涉条纹漂移的主要来源是机械振动与温度变化.md`。

## 命名规则

| 类型 | 格式 | 例子 |
| --- | --- | --- |
| 概念 | 结论句 | `étendue 守恒决定了亮斑不能被透镜无限放大.md` |
| 公式 | 名词 + 要点 | `菲涅尔公式的符号约定.md` |
| 现象 | 现象 + 解释 | `白光干涉只在零光程差附近出现彩色.md` |
| 错误 | 我曾搞错 + 正确说法 | `我曾把F数和数值孔径当成两个无关的量.md` |

## 清理节奏

- 每次会话结束：把 `capture/` 里当天的内容整理成原子笔记或删掉。
- 每周复盘：检查有没有 `capture/` 积压。
- 每季度：更新 `index/` 地图，删掉已被推翻的笔记（或标注"已推翻"）。
