## 为什么截图不公开

1. **截图里常有别的东西**——浏览器标签、账号名、通知弹窗、桌面文件名。
2. **岗位正文是第三方内容**，而且里面可能有招聘方的姓名与联系方式。
3. **体积**：截图会越攒越多，不适合放进仓库。

**但消化后的结论是公开的**：每条截图的岗位要求会被整理进
`../docs/13-岗位样本库.md`，那份文件进 Git，是长期资产。

一句话：**原始素材私有，结构化结论公开。**

## 怎么用（你做一步，我做四步）

**你做的**：在对话里直接发截图（可以一次发多张）。如果图里看不出公司和岗位名，
顺手写一句"这是 XX 公司的 XX 岗"。

**我做的**：

1. 把图存进 `inbox/jobs/YYYY-MM-DD-公司-岗位.png`
2. 读图，抽取结构化的要求（学历、硬性条件、技能、工具、职责）
3. 追加一条到 `../docs/13-岗位样本库.md`，并更新其中的累计统计
4. 回一句：**这条要求本项目覆盖了没有、缺口在哪**

## 一些约定

- **一张图一条记录**，编号连续（J-001、J-002……），不重排、不删除。
- 图看不清楚的字段就写"截图不清"，**不要猜**。
- 如果某条岗位明显不是光学方向（比如你顺手看的别的行业），
  我照样记，但在条目上标 `[非光学]`——它以后可能有用。
- 攒到 30 条以上时，把统计并回 `../docs/12-光学岗位要求与技能表.md` 的第 11 节。
