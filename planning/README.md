# 规划工作台

> 这套规则移植自本地 `D:\ysyx` 工作台（2026-09-23），那套已经跑了一个月，是被验证过的。
> 差别只在内容：那边是芯片设计，这边是光学。

## 编辑原则

1. **周清单只做增量修改，不整篇重写。** 计划有变就在当周文件末尾追加一行，或改勾选状态、加一行任务。
2. **大改只在一种情况下允许**：外部条件本身变了（例如降载模式启停、阶段验收标准调整）。改完在本文档的"变更日志"写一行原因。
3. **过期的周文件归档即可**，不要回头清理或重排——时间应该花在学习上，不是维护文档上。
4. **日志自动记录**：每次对话结束前，Codex 主动把当天的实质进展写进 `logs/daily-log.md` 的当天条目，**不等用户提醒**。
   只留"投入时长"和"遇到的问题"两项给用户填——那两项只有他自己知道。
5. **任务完成后自动勾选**：用户报告完成时，Codex 主动更新 `weekly/Wxx.md` 与 `weekly/Wxx-cards.md` 的勾选状态，**不等提醒**。
   同一条完成信息往往对应多处条目（本周任务 / 交付物 / 验收标准 / 任务卡），**要一次改全**。

6. **`today.md` 每天滚动更新，不等提醒**（2026-09-25 用户要求）：
   - 每次对话开始时，Codex 先看 `../today.md` 顶部的日期；**如果不是今天，就把它更新到今天**。
   - 更新内容三块：**今日最小任务量**（从 `weekly/Wxx-cards.md` 取编号最小的未完成卡，永远 ≤10 分钟）、
     **今日到期复习**（查 `notes/review-schedule.md`）、**加餐区**（先留空）。
   - 用户报告完成最小任务量后，**再往加餐区追加下一张卡**。
   - 最小任务量只有一张卡；**如果连这张也做不了，只打卡也算达标**。

## 每周怎么用

1. **周日晚上**：打开下周的 `weekly/Wxx.md`，把不需要的任务删掉，把要加的任务加上。**这个文件是你的，不是我的。**
2. **每天结束**：在任务卡上打勾，并在周文件底部"日志"区写三行（做了什么 / 卡在哪 / 明天第一步）。
3. **周日复盘**：把这一周的三行日志汇总成一段话，写进下一周文件的"上周回顾"区。
4. **每 4 周**：打开 `../docs/03-十年路线图.md`，对照阶段验收标准打勾。

## 任务卡的规矩（本系统的核心）

- **所有学习任务以 10 分钟为单位设计。** 不能出现"读完第 2 节（3 小时）"这类无法下手的任务。
- **每张卡必须标"在哪做"**：

| 标记 | 含义 |
| --- | --- |
| 【屏】 | 屏幕：读教材、看文档 |
| 【纸】 | **纸笔：推导、画图、算数，不许在屏幕上做** |
| 【机】 | 电脑实操：仿真、数据处理、仪器 |
| 【说/写】 | 复述或自测：说出来或打字都算完成，**关键是"不看资料、自己组织语言"** |

  **理论知识的深入理解，纸笔明显优于屏幕**；但系统性的任务拆分只有电子工具做得到。
  所以分工是：**电子负责"做什么、做到什么程度"，纸笔负责"怎么吃进去"。**
- **一张卡只引入一个新概念。** 如果一张卡需要同时用到两个以上的前置概念，就是拆得不够。
- **主动找"隐式前置"**：教材默认你已经会、却一个字没讲的东西（例如讲近轴近似时假设你会泰勒展开）。这是初学者卡住的最大来源。
- **卡片按需分批生成**，一批约 3 小时的量（20 张上下），不要一次铺开上百条。
- **10 分钟是任务粒度，不是每次只能干 10 分钟。** 坐下来通常连着做 6 张（约 1 小时）。

> **这套粒度也是降载模式的实现方式**：降载不是换一套计划，而是"每天只做一张卡"。
> 计划不用改，档位自己掌握。

## 怎么修改这些文件

全部是纯文本，改起来没有门槛：

- 勾选框：把 `- [ ]` 改成 `- [x]`
- 删除任务：直接删掉那一行
- 加任务：在列表里加一行 `- [ ] 你的任务`
- 觉得某周安排不合理：**直接改**，然后在下面的变更日志里写一行，说明为什么改

改完不需要重新生成任何东西，也不需要我参与。
