# 10 外部检验与公开计划

> 你的两条要求：可以公开在 GitHub，想要外部检验。
> 这两件事其实是同一件事：**公开是外部检验的前提**。

## 1. 为什么"自我感觉良好"必须被外部检验取代

光学的实验有个特点：**结果很容易看起来是对的**。
条纹出现了、光斑变小了、图像变清楚了——这些都可能在错误的理解下达成。

能骗过自己的东西，只有外部基准能揭穿：

- 你测的"波长"是不是真的？与原子谱线对一下就知道。
- 你测的"线宽"是不是真的？用第二种独立方法（自外差 vs 干涉长度）再测一次。
- 你的"复现步骤"完整吗？让别人照着做一遍就知道。

## 2. 外部检验的五个阶梯

| 级别 | 形式 | 成本 | 检验强度 |
| --- | --- | --- | --- |
| **L0 自校验** | 与自然常数、标准谱线、另一种独立方法对比 | 几乎为零 | 弱但必要 |
| **L1 公开留痕** | GitHub 仓库、Zenodo DOI、项目页 | 零 | 弱 |
| **L2 第三方交叉测量** | 让别人用不同设备/方法测同一个对象 | 低 | **强** |
| **L3 认证与竞赛** | 开源硬件认证、硬件竞赛、观测项目 | 低–中 | 中 |
| **L4 同行评议** | 期刊论文、预印本 | 时间成本高 | **最强** |

**L0 是最便宜的，也是你第一年就该做的。** 下面有一份现成的基准清单。

## 3. 现成的绝对基准（免费，且不可争辩）

这些是自然界的常数与原子谱线，任何设备测出来都必须一致。
**它们是你第一年就能用上的外部检验工具。**

| 基准 | 数值 | 用途 |
| --- | --- | --- |
| 汞灯 546.074 nm | 绿线 | 光谱仪波长标定 |
| 钠 D 双线 588.995 / 589.592 nm | 黄双线 | 高分辨光谱、分辨率验证 |
| 氖、氩、氪灯的多条谱线 | 见 NIST 数据库 | 多点波长标定 |
| 氘灯连续谱 | — | 紫外—可见连续光源 |
| 铷 D₂ 跃迁 780.24 nm | 原子绝对频率 | **激光绝对稳频基准** |
| 铯 D₂ 跃迁 852.35 nm | 原子绝对频率 | 同上 |
| 光速 c = 299 792 458 m/s | 定义值 | 波长↔频率换算 |
| CODATA 常数表 | — | 一切物理常数 |
| NIST Atomic Spectra Database | 免费在线 | 查任意谱线波长 |

**最低成本的外部检验方案**：买一支几元钱的汞灯或钠灯（或旧路灯灯泡），
用你的自制光谱仪测它的谱线，与 NIST 值对比。偏差就是你的系统误差。

## 4. 公开策略：仓库分层

这个仓库要公开，但**个人档案不该公开**。建议分两层：

```text
D:\Optics_Master\          ← 公开
├─ docs/                   方法论（可公开，甚至值得给别人抄）
├─ curriculum/             学习路线
├─ notes/                  知识笔记
├─ lab/                    实验记录与数据
├─ sim/                    仿真代码
└─ resources/              书单与资源

D:\Optics_Master\private\  ← 不公开（已加入 .gitignore）
├─ 私人记录.md
├─ 预算与采购流水.md
└─ 个人复盘.md
```

**原则**：方法论公开，个人信息私有，实验数据公开（除非涉及隐私）。

### 公开内容的红线

以下内容**永不进入公开仓库**：

- 真实姓名、单位、学校、所在地、联系方式
- 职业与学业状态、健康与家庭情况
- 具体收入、预算金额、消费流水
- 情绪与心理记录、失败与中断的细节
- 任何可以定位到"一个具体的人"的组合信息

可以公开的是：**约束的形态与由此推导的方案**。
例如"面向时间碎片化、无专用实验室的业余条件"，而不是"我每周几小时、没有房间"。

### 发布前检查清单

每次 `git push` 之前，尤其是首次公开或新增内容时：

- [ ] `git status` 里没有 `private/` 之外的意外文件
- [ ] 新增文档中没有出现真实姓名、单位、金额、健康信息
- [ ] 图片与截图里没有个人信息（屏幕内容、照片背景、文件路径含用户名）
- [ ] 检查 `git log` 的**提交信息**本身没有暴露信息
- [ ] 记住：**git 历史一旦公开就收不回来**，所以要在第一次推送前就处理好

> 如果发现已经公开了不该公开的内容，唯一的补救是**重写历史并强制推送**。
> 这在本仓库可以用 `git rebase --root` 或重建初始提交完成，越早做代价越小。

## 5. 许可证建议（需要你确认）

开源许可一旦确定很难撤销，所以由你决定。常见组合：

| 内容 | 建议许可证 | 理由 |
| --- | --- | --- |
| 文档、笔记、教程 | CC BY 4.0 | 允许转载，只需署名 |
| 代码（`sim/`） | MIT 或 Apache-2.0 | 宽松，便于别人使用 |
| 硬件设计（光机结构、电路） | CERN-OHL-S 或 CERN-OHL-P | 专门为开源硬件设计 |

**告诉我选哪个，我来加 LICENSE 文件。** 保守选择：文档 CC BY 4.0 + 代码 MIT。

## 6. L2 第三方交叉测量：怎么做到

这是性价比最高的强检验，但需要主动去找：

| 途径 | 做法 |
| --- | --- |
| 高校开放实验室 | 联系本地高校光学/物理实验室，说明项目，请求帮忙测一次（光束质量、波长、光谱） |
| 计量机构 | 中国计量院或省级计量院提供标准器校准服务（付费，但你买的是**溯源证书**） |
| 网友互测 | 在光学/激光/天文社区找到同好，互寄样品或互测数据 |
| 厂商测试服务 | 部分厂商提供元件检测服务 |
| 天文观测平台 | 观测数据上传到 AAVSO / NASA Exoplanet Watch，由专业系统检验 |

**第一年的可行目标**：把你的 G1 光源的波长与光谱，用第二种独立方法
（例如光栅衍射角法 vs 光谱仪）测一次，并与原子谱线对齐。这就完成了一次 L0。

## 7. 竞赛与项目（L3）：真实存在的渠道

| 渠道 | 类型 | 备注 |
| --- | --- | --- |
| Hackaday Prize | 国际开源硬件竞赛 | 光源类项目适合参赛，评审公开 |
| OSHWA 开源硬件认证 | 认证 | 费用低，标志你的设计符合开源硬件定义 |
| Zenodo | 发布预印本/数据集并获 DOI | 免费，可被引用 |
| NASA Exoplanet Watch | 业余望远镜观测系外行星凌星 | 真实科学贡献，数据被专业使用 |
| AAVSO | 变星观测 | 同上 |
| 全国大学生光电设计竞赛 | 竞赛 | **需要学生身份**，如果你符合则值得参加 |
| 天文摄影/观测比赛 | 竞赛 | 与你的望远镜兴趣吻合 |

**注意资格限制**：竞赛多有身份要求，报名前先确认。不存在资格限制的渠道
（Hackaday、OSHWA、Zenodo、AAVSO、Exoplanet Watch）优先。

## 8. L4 发表：现实预期

- **短期**：Zenodo 技术报告 + GitHub 开源设计 = 已经可以被引用。
- **中期**：如果 G3/G4 做出了新东西（例如极低成本的原子锁定方案），
  可以投 *Applied Optics*、*Optics Express* 或开放获取的硬件期刊。
- **长期**：G6 的"约束下最优"记录，本身就是有价值的可发表内容。

业余者发表论文的难点不是能力，而是**缺少对照实验和统计严谨性**。
所以从第一天起就养成写不确定度、写对照、写失败的习惯——
这恰好是 `06-评估与校准.md` 已经要求的。

## 10. 公开的隐性收益（值得写下来提醒自己）

1. **公开会强迫严谨**。知道别人会看，你会把假设和误差写清楚。
2. **别人会挑错**。每一个 issue 和质疑都是一次免费的外部检验。
3. **复现者会带来新的视角**。有人复现你的设计时，会暴露你没意识到的隐含假设。
4. **公开记录是长期动力**。看着自己的仓库增长，比任何打卡都有效。

**风险**：公开也会带来"表演型学习"的诱惑——为了更新而做，而不是为了懂而做。
对策：**只发布完成的、有数据的、自己敢复现的东西**，不发布"今天学了什么"的流水账。
